## Accessibility

- **axe** (`@axe-core/playwright` 4.14.0) runs on every screen in `e2e/responsive.spec.ts` at 390 and 1440 px (member, trainer, desk, finance, owner, branch manager and admin screens). Any serious or critical violation fails the test, with the rule, the elements and the fix. Rules: WCAG 2 A and AA, WCAG 2.1 A and AA, and axe’s best practices.
- **Found and fixed:** low-contrast “subtle” text (`clay-subtle` darkened to 4.7:1) and white-on-orange buttons (a new `ember-650`, 4.7:1, for buttons with white text; the marketing orange is unchanged); accessible names that did not contain the words shown (logo link, command palette button, sidebar items, “Remind”, “Accept with a note”, “Mark paid”, the exercise picker, “Back”, invoice links); a definition list with paragraphs in it; a scrolling step list that a keyboard could not reach; a phone card button that wrapped links.
- **Names follow what is shown** (WCAG 2.5.3): a link that shows a short word (“Start workout”, “Profile and settings”) is named by it, and the full wording is its tooltip.
- **Manual:** `docs/a11y-manual-check.md`, a 15-minute VoiceOver checklist for iPhone and Mac (login, log a set, book, desk check-in, pay an invoice). I cannot run a screen reader, so this is for a person.

## Demo guide and reset

- `/demo` (`pages/DemoGuidePage.tsx`, scenarios in `app/demoScenarios.ts`): six scenarios, each with one line on what it shows, who you are, and a **Start** button that signs in as that person (`signInDemo`) and opens the screen with a full load. Starting resets nothing (`e2e/demo-guide.spec.ts` checks the seed time is unchanged). Linked from the login page (“Try the demo as”) and from the account menu (demo mode only).
- The scenarios: log a workout as Arjun (`/m`), review a client as Coach Meera (`/t/clients/mem_arjun/review`), check in a member at the front desk (`/desk`), approve a refund as finance (`/desk/finance/refunds`), see the dashboard as the owner (`/owner`), support access as Ember admin (`/admin/support`).
- **Reset demo data** is a separate action: in the account menu and at the bottom of the guide, each asking first (“Keep my changes” is the focused choice). The account menu’s confirmation lives in `AvatarMenu`, not in the panel, because the panel closes the moment it is used.
- Fixed on the way: on phones the account menu ran under the bottom tab bar and hid Sign out; it is now capped above the bar.

## Lighthouse

`npm run build && npm run lighthouse` (`scripts/lighthouse.mjs`, Lighthouse 13.6.0). Mobile settings (Moto G Power, slow 4G, 4× CPU slowdown); three runs per page, the median saved; **return visit**: each page is opened once in a fresh browser profile first. The app pages (`/m`, `/t`, `/desk`, `/owner`) are signed in through the login page’s “Try the demo as” buttons and left on their home screen, then loaded again, so the demo gym exists and the scripts are cached. It serves `dist/` through a small server that compresses with brotli and caches hashed files for a year, as Vercel does (`vite preview` does neither). `LH_BASE=<address>` measures a deployed address instead. Exits with 1 under performance 90 or accessibility 100.

Result (`docs/lighthouse/summary.md`, one full report per page): performance 100 and accessibility 100 on all six pages; best practices 100; LCP 0.6 to 0.9 s; total blocking time 0 to 20 ms.

- **Found and fixed:** `/` scored 96 for accessibility, four small-text contrast failures in the home page’s mock-ups (small text in the marketing orange, a lilac date at 70% opacity, a mint label at 75% opacity). Each now uses the darker shade of the same colour, or full opacity. Nothing else on the page changed; `e2e/marketing.spec.ts` passes.
- SEO is 91 to 92 (not a target); the reports say what is left (the app pages are not meant for search engines).

## Deploy

- The GitHub repository is connected to the Vercel project `gym-ui-demo`. **A push to `main` deploys to production by itself**, so `main` is pushed only when the person who owns the demo has said so. A preview comes from pushing another branch (`m6-release`), which Vercel builds as a preview.
- `vercel.json` sets `VITE_DEMO_MODE=true` for the build, so the dashboard setting cannot turn demo mode off by accident. `e2e/pwa.spec.ts` checks that the production build is in demo mode (the sample logins, the demo guide, the reset).
- `npm run verify:deploy -- <address>` runs the checks that can run against a live address: the service worker and manifest tests (`PWA_BASE_URL=<address> npm run e2e:pwa`; the three tests that simulate a new deploy need the local test server and are skipped), the demo-mode check, the `sw.js` caching header, and Lighthouse on a return visit for the six pages (`LH_BASE=<address>`, reports in `docs/lighthouse/live/`).
- The preview of `m6-release` is `https://gym-ui-demo-git-m6-release-hari-darsans-projects.vercel.app`. Vercel builds it, but previews sit behind Vercel’s login, so the live checks need `VERCEL_PROTECTION_BYPASS` (the project’s “Protection Bypass for Automation” secret, in Vercel under Settings, Deployment Protection) or protection turned off for previews. Without one, `verify:deploy` stops and says so.
